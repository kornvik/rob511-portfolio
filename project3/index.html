AutoRob · ROB 511 · Project 3

Forward Kinematics + Live Visualization

A URDF-driven ROS-style runtime that computes forward kinematics for an arbitrary open-chain robot, broadcasts every link's pose over a rosbridge-style TCP/JSON gateway, and drives a choreography of joint setpoints — rendered live in a browser via three.js. For the demo I taught a 6-DOF arm the Queen's wave.

Rust rosbridge TCP/JSON URDF (hand-rolled XML parser) quaternions + 4×4 transforms three.js
Robot: arm6, three.js viewer my runtime · 10 Hz FK
Reference: Queen Elizabeth II via gifdb.com

The robot

Kinematic structure

A 6-DOF articulated arm modeled after a Trossen WidowX-style serial manipulator, described in hand-written URDF:

  • waist — base yaw (+Z).
  • shoulder — pitches about −Y.
  • elbow — pitches about −Y.
  • wrist_roll — rolls about the forearm axis (+X).
  • wrist_pitch — pitches about +Y.
  • gripper_yaw — final yaw at the hand (+X).

Each articulated joint carries a fixed-child "motor housing" cylinder so the arm actually looks like a robot in the viewer, not a stack of bare segments.

Why this shape

Six joints exercise every FK piece non-trivially: pitch joints that compose non-commutatively, a roll about a parent-dependent axis, and a yaw whose axis depends on everything above it. If any matrix math, quaternion extraction, or axis-angle rotation is wrong, the hand points the wrong way somewhere in the cycle.

The runtime loads this URDF through the same /param_server the autograder uses — no demo-specific shortcuts.

The choreography

Driven by a finite state machine that holds a table of joint-space setpoints. On entering a state the FSM publishes the setpoint on /joint_trajectory; a proportional joint servo moves each joint toward it; when every named joint lands within epsilon of its target, the FSM fires the state's on_arrival transition.

The video runs the wave choreography — a four-state loop:

  • home — all joints at zero.
  • arm_up — elbow bends to +π/2; the arm forms an "L" with the forearm pointing straight up and the palm pre-rolled to face the crowd.
  • wave_right — wrist_roll sweeps right, the waist leans slightly in that direction, and the elbow wobbles ~5° to add a bit of organic shake.
  • wave_left — the mirrored pose; then the FSM loops back to wave_right indefinitely.

Each transition fires the moment every named joint lands within 0.08 rad of its target, so the arm commits to each pose fully before starting the next one. Because the forearm points up (world +Z), rotating wrist_roll becomes a pure yaw about the world vertical — which is exactly what makes a human wave look like a wave.

How it's drawn

The viewer is a static three.js page (index.html + viewer.js) that opens a WebSocket to a small Python relay (bridge.py). The relay forwards newline-delimited JSON between the browser and the runtime's TCP gateway on 127.0.0.1:9095 — the browser can't open raw TCP sockets, but everything else is vanilla rosbridge.

On startup the viewer:

  1. Reads robots/arm6/arm6.urdf from disk.
  2. Calls /param_server/set_param with the URDF, waits for /robot_state_publisher/description_status to accept it.
  3. Parses the URDF's <visual> elements and builds one three.js Group per link, with box / cylinder / sphere geometries.
  4. Subscribes to /xform_world and, on every message, applies the 4×4 matrix of each link's node with matrix.fromArray(t.matrix). The matrix layout is column-major and matches THREE.Matrix4 exactly, so no transpose is needed.

Node graph

external clients (grader, viewer, …) | TCP / JSON (127.0.0.1:9095) | rosbridge gateway | param_server (robot_description, description_status) | v robot_state_publisher <-- /joint_states -- joint_state_publisher (demo) | ^ /tf (parent → child, per joint) | /joint_trajectory | | v | robot_world_state_publisher <-- /global_pose finite_state_machine (demo) | /fsm/* services | v /xform_world (every link, 4x4 matrix in global_frame)

Mathematical core

Transforms

  • rpy = Rz(yaw) · Ry(pitch) · Rx(roll), fixed-axis.
  • Joint transform T_joint(q) = T_origin · T_motion(q).
  • Revolute/continuous: axis-angle (Rodrigues), axis normalized.
  • Prismatic: translation along axis AS WRITTEN (not normalized).
  • Fixed: identity.

Quaternion extraction

Rotation-matrix → quaternion uses the four-branch extraction (pick the largest of w², x², y², z² first). The trace-only formula divides by a near-zero number near a 180° rotation; the four-branch version is numerically stable everywhere.
